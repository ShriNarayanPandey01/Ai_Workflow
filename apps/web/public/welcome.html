ai.chat-model@1 · typed ports

Every wire is typed.

Nodes publish input and output schemas. The builder binds fields between them, and nothing ships until both ends agree.

Mismatched types fail validation before a run starts — twice: once when you publish, once again when the engine picks it up.

control.condition@1 · durable runs

Runs survive restarts.

Each step writes a checkpoint before the run moves on. If a worker dies mid-flight, the engine leases the run to another worker and resumes from the last checkpoint.

step starts→ output persisted→ checkpoint written→ next step leased
  • At-least-once delivery, deduplicated by inbox
  • Bounded loops — every cycle has a budget
  • Retries with exponential backoff and jitter

human.approval@1 · humans in the loop

You are a node in the graph.

Approval and review steps pause the run and hold it — minutes, hours, days, whatever the decision takes. State stays intact the whole time.

The demo above stopped and asked you. Production runs ask your team the same way — from the Approvals queue, with full context attached.
